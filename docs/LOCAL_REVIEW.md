## 结论与边界

检查了项目全部 Python 源文件、依赖声明、测试脚本、Git 配置和启动入口；未发现恶意命令执行、系统持久化、浏览器凭证窃取或向陌生站点外传数据的明显行为。老板键只渲染静态构建日志，没有执行 npm。

原始版本存在需要先修复的安全问题，已在当前工作区修补。修补后的离线测试和公开接口联网检查通过，可启动到登录页。账号扫码确认、登录后的个人资料和关注列表仍需本人完成后验证。静态检查和漏洞数据库扫描不能证明第三方软件绝对安全，也不等同于对所有原生依赖的完整源码审计。

没有替用户扫码登录、获取账号凭证、发帖或修改远端账号数据。运行时登录凭证仍是本地明文文件，权限 600 和 Git 忽略规则降低误读与误提交风险，不能替代磁盘或钥匙串加密。

## 发现与修复

1. **高风险：第三方依赖关闭证书校验，部分 API 使用 HTTP。** 实际安装的 aiotieba 4.8.2 在连接器和请求上均关闭 TLS 校验，get_threads/get_bawu_info 等使用 HTTP。本项目新增独立 VerifiedClient/VerifiedNetCore，限定百度 API 主机，将 HTTP 请求在发送前升级为 HTTPS，并强制证书链和主机名校验。图片和扫码会话也使用 certifi CA。未修改 site-packages 或全局 aiohttp 行为。适配依赖内部字段，因此固定 aiotieba 版本，并加入回归检查；项目没有启用其 WebSocket 或聊天通道。
2. **凭证权限和写入。** config.yaml 改为同目录临时文件（600）写入后原子替换，写入失败保留原文件；临时文件加入 Git 忽略规则。换号时清除旧 STOKEN，防止跨账号混用。
3. **不受限的图片请求。** 限制百度图片域名（baidu.com/bdimg.com/bcebos.com）、HTTPS 和端口，逐次检查跳转；浏览器打开图片也验证同样规则。每张图片下载限制 15 MiB，解码限制 2400 万像素。超限请求不写入缓存。百度生态之外的图片将被拒绝，这是有意保留的限制。
4. **远端文本标记。** 帖子标题、用户标题、状态栏和登录状态使用纯文本渲染，降低远端 Rich 标记注入风险。
5. **依赖可复现性。** 从官方 PyPI 下载 wheel，不执行来源包构建脚本；新增带 SHA-256 的 requirements.lock，覆盖本机 30 个应用依赖。漏洞审计工具在 /tmp 的独立环境运行，未加入应用依赖。
6. **可用性。** 修复 CLI 登录没有二维码显示、搜索输入 q 触发退出、二维码使用不利扫码的 braille 渲染、重复扫码并行任务问题；macOS 使用非 Sixel 渲染时跳过无用终端探测。补充 start.command 启动入口和正确的模块化测试命令。

## 使用

在项目目录执行 `./.venv/bin/python main.py`，或双击 `start.command`。本程序是终端应用，不监听本地 Web 端口。点击「扫码登录」，放大终端后用百度 App 扫码并确认；按 q 退出，反引号切换老板键。

当前代码和依赖适配均为本地未提交修改；未创建提交、推送或改动 GitHub 仓库。
